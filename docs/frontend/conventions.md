# Frontend conventions

## Source of truth

- Entry: `frontend/src/main.ts`
- Router: `frontend/src/router.ts`
- HTTP helpers: `frontend/src/api.ts`
- App shell: `frontend/src/components/App.vue`
- Client stores: `frontend/src/stores/`
- Frontend package pins: `frontend/package.json`
- HTML shell: `frontend/index.html`
- PWA registration: `frontend/src/pwa.ts`; SW generation: `src/musicweb/pwa_shell.py` + `routes/pwa.py` (see `docs/systems/pwa.md`)

## Architecture

- **Vite + `@vitejs/plugin-vue` + `vue-tsc`.** Vue and Vue Router are package deps. Components are `<script setup lang="ts">` SFCs; other modules are TypeScript. Imports use the `@/` alias (`frontend/src/`), a `.vue` suffix for SFCs, and extensionless TypeScript specifiers. Dev is `pnpm --dir frontend dev` (proxies `/api` to FastAPI `:8765`). Production is `pnpm --dir frontend build` (`vue-tsc` then Vite); FastAPI serves `frontend/dist` and replaces the `#musicweb-config` script body. SW registration skips when `import.meta.env.DEV`.
- **SPA fallback:** FastAPI serves the same shell for client routes so refresh works on `/artists`, `/artists/…`, etc.
- **Stores** hold player, playlist/queue, settings, and UI chrome. Components should prefer store APIs over ad-hoc globals. The `player` record lives in `playerState.ts`; covers/Media Session metadata in `playerSession.ts`; volume/expanded keys in `playerPrefs.ts`. `player.ts` owns on-demand transport and sink wiring and re-exports `player`. Play decision is `resolvePlayIntent` / `shouldPrepare` / `isPlayableNow` in `playback/playIntent.ts`. Exclusive-aware `{ sink, profileFor }` is `playback/deliveryPolicy.ts` (the only `isExclusiveEnabled` reader on the play path). HTML delivery is `resolvePlaySource` in `downloads/resolve.ts` (source / url / profile / block — no sink); radio `loadCurrent` calls it directly. `resolvePlayIntent` is the only constructor that attaches `htmlAudio` or `companion` (do not call it from radio). Load/fail lives in `playback/load.ts` (`loadResolved`, `beginLoad`); unavailable/load failures go through `failCurrentLoad` (`reason`, optional `message` / `toast`) — the only fail writer. Sink/load failures are `PlayBlockError` (`playBlock.ts`). The exclusive device gate is `companionSink.load`. Prepare is `prepareTracks` in `playback/prepare.ts` (`preparedKeys`, `requestPrepare`, `requestForget` live there, not in `api.ts`). Handoff is `become("none" | "queue" | "radio")` in `playback/session.ts`. Shared HTML element helper is `playback/sinks/htmlElement.ts`. `beginLoad` stops the HTML sink only; companion stops when the new intent is unavailable or the sink changes (`needsCompanionStop` next to `PlayIntent`). Exclusive track-to-track does not release the companion. `stopPlayback` / leaving queue via `become` tears down both sinks and revokes the local blob. Volume face + storage is `setOutputVolume` in `playerPrefs.ts` (the only writer); `initOutputVolume` / `initRadioListeners` run from `main.ts` before `createApp` — on-demand subscribes `getActiveSink().setVolume`, radio subscribes `radioAudio.setVolume`. Offline queue skip uses `isPlayableNow` in `playIntent.ts` (`isOfflineUnplayable` remains the skip-mode gate). `player.ts` does not import `radio.ts`. `setStreamCodec` persists only (no play index, no prepare). `player.ts` watches `settings.streamCodec` and `settings.playbackPolicy` and owns queue reload plus prepare-on-change. Radio watches `settings.playbackPolicy` from `initRadioListeners()` (same boot as `initOutputVolume`) and re-resolves while `tuning` / `tuned`. Exclusive prefs live in `exclusiveAudio.ts` (`setExclusiveLive` for live fields); that store does not import `companionClient`.
- **Library UI** lives under `components/library/`. `App.vue` mounts one `LibraryView` for online and downloads (`meta.mode === "downloads"`). Load, navigate, `flags`, `chrome(input)`, `cover()`, menu `run`s, tree `loadRoots` / `loadChildren`, plus tree title / empty copy / focus path / reload keys live on a `BrowseSource` (`onlineBrowse` / `downloadsBrowse`); list and tree both call `entityActionsFor(source)`. Hosts do not switch on mode for those jobs. Browse `artUrls` keys match `art.ts`: `artist:${id}:thumb` and `cover:${albumId}:thumb`. Downloads tree kinds are `artist` / `album` / `track` (same as online). `loadDownloadsView` returns `LibraryPage`. **Stats** is a template body inside the mounted `LibraryView` (`/stats`, `components/stats/`); `load()` is not called and there is no stats chrome mutation. Player UI is under `components/player/`; settings modal under `components/settings/`. Listen policy, outbox, and chips live in `frontend/src/listens/` — see `docs/systems/playback-stats.md`.
- **Row action menus** live under `components/menu/` (`ActionCard`, `AnchoredMenu`, thin `ActionMenu` picker). Entity list/tree/header menus use `useEntityMenu` (key/target/toggle); `useRowActionMenu` owns anchor/focus only. Callers pass items with `run()`. Do not add `stores/actionMenu.ts`. Do not add an `actions` mode to `dialog.ts`. A second surface mounts its own picker; do not invent a second overlay system.
- **Row covers:** omitted or `null` `coverSrc` keeps the row’s remote fallback (`artistImageUrl` / `coverUrl`). `""` means placeholder (`resolveRowCover` in `rowCover.ts`) — downloads must not invent `/api/cover` or `/api/artist-image`.
- **Downloads** (`frontend/src/downloads/`) own the client offline catalog (IndexedDB + OPFS or companion disk). Public import stays `@/downloads/catalog` (barrel over `projection.ts`, `art.ts`, `writer.ts`). Catalog records are storage-only; the queue snapshot is a `Track`. One catalog view is cached `loadDownloadsCatalogView()` in `snapshot.ts` (`invalidateDownloadsCatalogView` from `writer.ts` mutations). `TreeNode` is the discriminated union in `components/tree/treeNode.ts`. `queue.ts` is IDB + the live progress `Map`; abort of in-flight work is `queueRuntime.ts` (`freezeActive` / `cancelItem`); `queue.ts` does not import runtime. Worker is I/O. Companion blob client is `companionBlob.ts`. The concurrent-downloads picker is Settings chrome bound to `downloads.concurrency` / `setDownloadConcurrency`, not a quality field on `settings.ts`. Saved playlists expose camel `trackCount` (mapped once in `fetchSavedPlaylists`). Keep offline concerns out of server index code. Design: `docs/systems/downloads.md`.
- **Playback / quality** (play source, stream vs download policy, prepare): `docs/systems/playback.md`.
- **Exclusive audio** (Mac PWA hog + companion sink; optional): `docs/systems/exclusive-audio.md`. Desktop companion Settings (`CompanionPanel`) is separate from Exclusive audio. Player transport goes through sinks — do not re-export a shared `HTMLAudioElement` from `player.ts`. Sidecar: `docs/systems/companion.md`.
- **Connectivity** (online / offline / server_down): `docs/systems/connectivity.md`.
- **Diagnostics** (`frontend/src/diag/`): always-on emit with an Errors only / Everything cutoff in Settings. Same-origin `/api` fetches share the helper in `api.ts`. Design: `docs/systems/diagnostics.md`.

## Frontend package

Pinned Vue/Router and toolchain versions live only in `frontend/package.json`. Commit `frontend/pnpm-lock.yaml`. Do not commit `frontend/dist`.

To upgrade Vue/Router: change the version in `frontend/package.json`, run `pnpm --dir frontend install`, and rebuild.

## UX conventions

- Mobile: bottom tab bar (Library | Playlist | Radio) + mini-player / expanded now-playing. The inactive library/queue pane is `.hidden` on the `.view` root. On `/radio`, `App.vue` **`v-if` unmounts** library+playlist (do not CSS-hide a still-mounted `LibraryView`) and `#player` is hidden. Desktop (`min-width: 900px`) **hides** `#tab-bar`; Library/Playlist stay mounted as the dual-pane. Radio is chrome, not a pane: `RadioNowPlaying` `layout="room"` occupies the expanded `#player` right rail. The Queue header Radio icon toggles that rail. Desktop `/radio` opens the rail and `replace`s to the last library URL. Do not add Radio as a ModeBar chip. `effectiveLibraryMode` stays radio-free.
- **Browse mode chips** (`ModeBar.vue`, `frontend/css/library.css`): one labeled row, horizontal scroll, no wrap, do not shrink below the label. Selected id is `useLibraryLocation()` (last library on `/queue`), via `effectiveLibraryMode` in `browseMode.ts` — not raw `route.meta.mode`.
- **Queue view-bar:** icon-only actions below 900px; labeled pills at/above. Glyphs live in the `frontend/index.html` sprite.
- Desktop: two-pane library + playlist with persistent player bar (breakpoint owned by CSS). On-demand now-playing is `NowPlayingView` inside `NowPlayingFull`. Radio mounts the same `NowPlayingView` from `RadioNowPlaying` (room in the desktop expanded rail; room on mobile `/radio`; compact bar off the rail on desktop). Compact-bar cover opens the rail on desktop and `/radio` on mobile. Off `/radio` on mobile, radio chrome is `RadioMini` only. `radio/runtime.ts` is socket only; `radio/session.ts` owns face/load (`onFaceOrTrack`, `loadCurrent`) and radio Media Session; radio audio implements `PlaybackSink` (`kind: "htmlAudio"`) on its own element. `stores/radio.ts` is the chrome face. One `socketRequired`; `connected` tracks socket open. Tuner codec is a `browser_listed` profile, never `source`. Changing Streaming while radio chrome is on re-sends `tune_in` (`setStreamCodec` has no play index), then `loadCurrent` re-resolves. Changing **When a download exists** while `tuning` / `tuned` re-resolves the current official track.
- Codec list in settings reflects **probed** browser decode support (`codecSupport.ts` / related probes), not a static marketing list alone — see `docs/systems/playback.md`.
- **Tracks, albums, and artists** normalize at the API boundary (`models/track.ts`, `models/album.ts`, `models/artist.ts` via `fromApiArtist`). Those leaves use camelCase — including album `lossyKind` and artist `albumCount` / `preferredRev`. Status face is `PlayStatusState.session` (`none` | `queue` | `radio`) ⊕ source; exclusive snap is ignored when `session === "radio"`.
- **Lossy marks:** `LossyMark` is a button (hover `title`, `aria-label`, tap → `showToast`). Do not nest it inside another `<button>`. Icon tap must not play, expand, or navigate. No long-press. Copy lives in `lossyKind.ts`.
- **No native browser dialogs.** Use `confirmDialog` / `promptDialog` from `stores/dialog.ts` (themed via `AppDialog`) for blocking confirm/prompt flows, and `showToast` from `stores/ui.ts` for transient errors and soft info. Do not call `alert`, `confirm`, or `prompt`.
- **Selection.** App chrome is not a document. `frontend/css/app.css` sets `user-select: none` (and `-webkit-touch-callout: none`) on `html, body`. Opt `user-select: text` back in only for `input`, `textarea`, `[contenteditable]`, and `.lyrics-plain`.
- **Copy.** All clipboard writes go through `copyText` in `clipboard.ts` (toasts “Copied” / “Could not copy”). Empty values are omitted from menus, not copied as blank. Settings diagnostic IDs use the same helper. ActionMenu copy rows (including Copy lyrics) set `icon: "copy"` against `#i-copy` in `frontend/index.html`. Settings diagnostic Copy pills stay text-only.
- **Action-menu chrome** follows `(min-width: 900px)` via `layout.ts` (`DESKTOP_MEDIA`, `useDesktopViewport()`): centered card below, anchored dropdown at/above. Same breakpoint as the dual-pane shell. New client code does not copy the query string. Close the menu before `confirmDialog` / `promptDialog` (picker closes, then `run()`). The card acquires modal-lock token `"action-menu"`; the desktop dropdown does not. Desktop `contextmenu` opens the same menu (no native browser menu; no long-press unless product revisits it). The caller closes on route change (and queue Edit); the picker does not import the router. One `ActionMenu` per host; no `stores/actionMenu.ts`.
- **Entity `⋯`.** Artists, albums, tracks, and queue have overflow on list, grid, and tree. Artist and album **page headers** (online and downloads) and **expanded now-playing** (`.sheet-grab`) also have `⋯`. Mini-player and the lyrics overlay do not. `showMenu` (default false) opts a shared row/card into `⋯` (replaces `+` / chevron). Track-row **DownloadIcon** and page-level Add all / Download pills stay. Item order lives in the builders: `artistMenuItems`, `albumMenuItems`, `trackMenuItems`, `queueMenuItems`, `nowPlayingMenuItems`. Album and artist menus put **Play all** immediately under **Add all to playlist** (list, grid, tree, headers). Play all replaces the session playlist and starts the first track. The page **Add all** pill and track **Add to playlist** stay append-only. Mutating actions are injected `run`s; downloads hosts pass `downloads/addAll.ts` (catalog only) for both add and play.
- **Artist photo menu** is on artists list, grid (visible `⋯` plus desktop right-click), tree, and the **online artist-page header**. Search, downloads (rows, tree, header), queue, and now-playing do not get a photo menu. `showMenu` and `includePhoto` are separate props; `includePhoto` is photo items **and** drop-to-crop. Cropper chrome is `artistArt/cropper.ts` + `ImageCropper` in `App.vue` + `cropper.css`; system back copies Vue Router `history.state` and never changes path. Overlay lives in `artistArt/state.ts` (`pending` is `"upload" | "revert"`). HTTP success goes through `applyPreferredServerResult`. Helpers throw `PreferredRequestError` with `.status` via exported `apiFetch`. Modules `upload.ts` / `submit.ts` / `pending.ts` stay acyclic. `artistImageUrl` appends `&rev=` on any nonzero `preferred_rev`. Pending boot is `initArtistArtPending()` from `main.ts`; pending rows live in `musicweb-artist-art`, not downloads IDB.
- **Now-playing cover flip** is the only now-playing artist-photo surface (expanded sheet/panel and radio room — not mini or compact bar). It does **not** add photo items to `nowPlayingMenuItems`. Eligibility is `coverFlip.ts`: `fetchArtist` then `artistImageUrl(..., "full")` with `preferred_rev`. Flip is off while `canReachServer()` is false. Lyrics overlay blocks the tap and does not change the face.
- **Lyrics copy.** Plain lyrics (`.lyrics-plain`) stay selectable and copy as-is. Synced lines are not selectable (tap-to-seek). Copy lyrics flattens via `parseLrc` (no timestamps; drop empty/`♪`; collapse consecutive dupes) in `lyrics/plainText.ts`. Visibility uses sync `peekLyricsMemory` only — hide when a real peek exists and there is nothing to copy. `run()` always `resolveLyrics` then copy or toast “No lyrics to copy”.
- **Modal scroll lock:** `stores/modalLock.ts` acquire/release tokens only — settings, downloads manager, dialog, and the action-menu card must not toggle `body.modal-open` directly.
- **Interactive downloads:** user-facing `downloadTrack(s)` and `confirmRemoveDownloadedTrack` live in `downloads/ui.ts` (leftover-migrate / remove confirms). Pure enqueue / lifecycle stay in `downloads/index.ts` (no dialog imports). Download **kind** join (`downloads/actionKind.ts`) returns `{ kind }` only; icon titles, glyphs, disabled, and menu labels stay with their callers. Details: `docs/systems/downloads.md`.

## Guardrails

- Do not revert to a CDN import map without a new decision (see technical decisions).
- Prefer stable track IDs in client state and playlist APIs over raw filesystem paths.
- Keep CSS split by concern under `frontend/css/`; avoid inline sprawl for large features.
- Do not commit `frontend/dist`; hosts build it with `pnpm --dir frontend build`.
